# Plynt(플린트) 0.1.0-preview.3

여러 AI의 대화·작업 화면과 다시 쓸 글을 한곳에 모으는 앱입니다. Naru에서 **Plynt**로 이름을 변경하고, 표시 이름과 설치 파일 이름을 맞춘 사전 릴리스입니다.

## 다운로드

아래에서 운영체제와 CPU에 맞는 파일을 선택하세요. GitHub의 **Assets**에 첨부된 파일이 설치 파일입니다. `Source code.zip`은 개발 소스입니다.

| 환경 | 파일 |
|---|---|
| Windows x64 설치 | `plynt-0.1.0-preview.3-win-x64.exe` |
| Windows x64 무설치 | `plynt-0.1.0-preview.3-win-x64.zip` |
| macOS Apple Silicon | `plynt-0.1.0-preview.3-mac-arm64.dmg` 또는 `.zip` |
| macOS Intel | `plynt-0.1.0-preview.3-mac-x64.dmg` 또는 `.zip` |
| Linux x64 AppImage | `plynt-0.1.0-preview.3-linux-x86_64.AppImage` |
| Debian·Ubuntu x64 | `plynt-0.1.0-preview.3-linux-amd64.deb` |
| Android 호환성 시험 | `plynt-0.1.0-preview.3-android-test.apk` |

`SHA256SUMS.txt`에는 함께 배포한 파일의 SHA-256 체크섬이 있습니다.

## 변경 사항과 기존 설치

- 앱 화면·창 제목·Android 메뉴·진단 파일명·설치 파일명을 Plynt로 변경했습니다.
- 최대 30개 탭, 최대 4개 멀티뷰 패널, 대상 탭으로 이동하는 글 전달 기능은 유지합니다.
- 기존 작업·로그인 데이터에 계속 접근할 수 있도록 데스크톱 데이터 경로와 앱 ID, Android 패키지 ID를 유지했습니다. 프로필이나 세션을 다른 위치로 복사하지 않습니다.
- Android 버전 코드는 3입니다. 시험 APK는 디버그 서명이며 CI 빌드마다 서명 키가 달라질 수 있습니다. 기존 APK와 키가 다르면 바로 업데이트할 수 없으며, 앱 삭제 시 로컬 데이터가 사라질 수 있습니다.

## 검증 범위

Plynt 이름 변경 코드에서 Linux 합성 화면 검사 30개와 재시작 검사 6개, 실제 창의 표시 이름을 확인했습니다. 이번 릴리스의 설치 파일은 GitHub Actions에서 Windows·macOS·Linux 빌드와 Android APK 빌드가 모두 성공한 뒤 게시됩니다. **빌드 성공은 해당 OS에서 실제 서비스에 로그인하거나 프롬프트를 전달하는 시험의 성공과 다릅니다.**

데스크톱은 코드 서명·Apple 공증을 하지 않은 프리뷰입니다. Android APK는 WebView 호환성 시험용이며 완성된 모바일 앱이 아닙니다. Android 길게 누르기 전달과 정상 로그인 완료, Windows·macOS의 실제 앱 실행, Suno·Canva 로그인 후 전달은 미검증입니다. iOS 설치 파일은 없습니다.

메시지 전송·유료 생성·외부 게시 버튼을 자동으로 누르지 않습니다. 진단 보고서는 기기에만 기록하며 사용자가 직접 내보냅니다.

## English

Naru is now **Plynt**. This preview aligns the app's display name and installer filenames while keeping existing desktop profile paths and application identifiers. It retains up to 30 task tabs, up to four multiview panels, and selected-text transfer that activates the destination tab.

Choose an installer from **Assets** using the platform table above. `Source code.zip` is not an installer. `SHA256SUMS.txt` lists checksums. Release publication requires successful Windows, macOS, Linux, and Android build jobs.

Linux synthetic-page checks and restart checks passed for the renamed app. Successful packaging does not establish runtime compatibility or authenticated service support. Desktop builds are unsigned and not notarized. Android is a separate debug-signed compatibility preview; signing keys can differ between CI builds, preventing an in-place update. Uninstalling an old APK can delete local data. There is no iOS installer.

Authenticated Suno/Canva transfers, completed Android sign-in and long-press transfer, and actual Windows/macOS app execution remain unverified. Diagnostics stay local until manually exported. The app does not automatically send messages, consume generation credits, or publish content.

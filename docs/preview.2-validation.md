# 0.1.0-preview.2 변경 및 검증 기록

시험일: 2026-11-17 UTC. 데스크톱 변경은 Linux의 실제 Electron 창에서 확인했습니다. Android는 공식 에뮬레이터를 실제 부팅하고 별도 시험 APK를 설치·실행했지만, 서비스 로그인과 길게 누르기 전달의 완료는 아직 검증되지 않았습니다.

## 데스크톱 변경

- 탭은 최대 **30개**, 멀티뷰 구성원은 최대 **4개**입니다. 31번째 탭 추가는 설명과 함께 중단합니다.
- 새 탭은 단독 화면으로 열립니다. 멀티뷰에 없는 탭을 선택해도 기존 패널을 교체하지 않습니다.
- 멀티뷰 구성원 탭을 선택하면 기존 구성·순서·분할 너비로 돌아옵니다. 단독 표시와 저장된 멀티뷰 구성을 별도로 관리합니다.
- `멀티뷰` 대화상자에서 함께 볼 탭과 2×2 / 좌우 4열 배치를 직접 선택합니다. 네 개를 선택하면 다른 체크박스는 비활성화됩니다.
- 활성 탭은 은은한 배경·테두리·밑줄과 `aria-selected`로 표시합니다. 글 전달 시 대상 탭이 탭바 안으로 스크롤되고, 해당 화면과 입력칸으로 이동합니다.
- 전달은 화면 배치가 적용됐다는 응답을 기다린 뒤 실행합니다. 기존 고정 100ms 대기 대신 실제 표시 상태를 확인합니다.
- 단독 화면에서 중복 패널 머리글을 숨겼으며, 중성색 배경·통일된 도구 아이콘·작은 서비스 배지·여백으로 UI를 정리했습니다.
- 기존 프로필 경로와 앱 식별자를 유지합니다. 기존 저장 형식의 탭·글·배치를 읽으며, 기존 버전이 전체 파일을 버리지 않도록 저장 파일의 버전 식별자는 유지했습니다.

## Android 구현과 실제 시험

[Android 시험 앱](../mobile/android/README.md)은 원본 웹사이트를 Android WebView로 열고, 길게 눌러 나타나는 선택 메뉴에 전달·입력칸 지정·보관 기능을 추가합니다. 데스크톱의 입력 검사 코드를 공유하지만 네이티브 UI와 WebView 연결은 별도 구현입니다. 모바일 멀티뷰와 iOS 앱은 포함하지 않았습니다.

| 항목 | 실제 환경·관측 |
|---|---|
| 호스트 가속 | `/dev/kvm` 없음. 하드웨어 가속을 사용하지 못함 |
| 에뮬레이터 | Google 공식 Android Emulator 37.2.13 |
| 시스템 이미지 | Google Play Android 15, API 35, x86_64, revision 9 |
| 기기 | `sdk_gphone64_x86_64`, 480×960, 3,072MiB RAM |
| WebView / Chrome | 124.0.6367.219. 최신 실기기 WebView와 동일한 환경은 아님 |
| 초기 실행 설정 | 가상 CPU 2개, SwiftShader, `-accel off` |
| 재시험 설정 | 같은 기기에서 CPU 1개, `-gpu off`, 하드웨어 가속 없음 |
| APK 도구 | Google 공식 API 35·build-tools 35.0.0, Eclipse Adoptium JDK 21.0.13+9 |
| 다운로드 검증 | Android 도구는 공식 저장소 SHA-1, JDK는 공식 릴리스 SHA-256과 일치 |
| 앱 ID / 버전 | `dev.naru.mobile.preview` / `0.1.0-preview.2` |

| 시험 | 판정 | 근거·원인 구분 |
|---|---|---|
| Android 부팅·adb 연결 | 성공 | 실제 Android 15가 `sys.boot_completed=1` 반환 |
| APK 빌드·서명 검증·설치 | 성공 | 공식 SDK 도구로 빌드, apksigner 검증, adb 설치 성공 |
| Naru 네이티브 첫 화면 | 성공 | 탭바·추가·메뉴와 시작 화면 표시, `app.start` 진단 확인 |
| Suno 공식 페이지 진입 | 실패 | 초기 `-5`(프록시 인증 오류), 설정 변경 후 `-2`(호스트 조회 실패), 마지막 연결에서 TLS 오류 `3`(인증기관 신뢰 실패)로 중단. 시험 환경의 네트워크·신뢰 경로 문제이며 서비스 미지원으로 판정하지 않음 |
| 실제 계정 로그인 완료 | 미검증 | 로그인 화면 검증이 막혔으며 계정 인증도 수행하지 않음 |
| 실제 Android의 길게 누르기 → 입력 | 미검증 | 합성 WebView 렌더러 종료로 끝까지 실행하지 못함 |
| Android 합성 페이지 렌더링 | 재현된 오류 | 두 페이지에서 `page.crash`; 시스템 크래시 버퍼에 WebView 렌더러 `SIGTRAP`. GPU·CPU 설정을 바꾼 마지막 실행에서도 두 합성 페이지의 종료 재현. 근본 원인은 미확인 |
| 시험 기기 안정성 | 문제 확인 | Digital Wellbeing·Pixel Launcher·System UI의 ANR와 Bluetooth 프로세스 반복 종료도 관측 |
| Android 진단 파일 | 일부 성공 | 앱 전용 JSON에서 실행·페이지 오류·렌더러 종료 이벤트 확인. 파일 선택기로 내보내는 동작은 미검증 |
| Chrome 기준 브라우저 | 미검증 | 기기 전체의 응답 지연으로 정상 웹 작업까지 확인하지 못함 |

이 결과를 “Android에서는 로그인할 수 없다” 또는 “특정 서비스가 Naru를 차단한다”는 증거로 사용하지 않습니다. 시험 환경의 프록시·성능 문제와 원인이 확인되지 않은 WebView 종료가 섞여 있습니다.

에뮬레이터는 상속된 환경 프록시를 사용하는데 기기 내부에도 프록시가 설정되어 있었습니다. 내부 중복 설정을 정리했고, 시험과 무관하게 반복 종료되는 Bluetooth는 정상 설정 명령으로 껐습니다. GPU·CPU 설정도 바꿔 재시험했습니다. 마지막에는 호스트의 기존 프록시로 연결하는 로컬 TCP 중계와 adb reverse를 이용해 기기의 DNS 문제를 분리했습니다. 통신 내용을 기록하거나 TLS를 해제하지 않았으며, 이후 Suno 연결은 인증기관 신뢰 오류로 차단됐습니다. 인증서 검증이나 서비스 인증을 우회하지 않았습니다.

마지막 실행에서도 System UI 응답 없음과 합성 WebView 종료가 재현됐습니다. 로그인 완료와 길게 누르기 전달은 끝내 입증하지 못했으므로 **미검증**으로 남깁니다. 시험 후 에뮬레이터와 시험용 로컬 중계를 종료했습니다.

관측에 따라 앱도 보완했습니다. WebView 초기화를 빈 시작 화면에서 미뤘고, 페이지 오류 후 완료 콜백을 성공으로 기록하지 않게 했습니다. 렌더러가 종료돼도 탭 이름·주소를 유지하고 다시 열 수 있도록 했습니다. 진단은 허용된 필드만 최대 300개 유지하고 재실행 시 복원합니다. 이 보완 코드의 존재가 Android 전 과정을 검증했다는 뜻은 아닙니다.

## 배포와 다음 검증

데스크톱 변경은 시험판에 반영합니다. Android APK는 **호환성 시험용 디버그 빌드**로 구분하며 데스크톱과 같은 수준의 검증을 마쳤다고 소개하지 않습니다. CI가 만드는 설치 파일의 생성 성공과 실제 OS·서비스 실행 성공도 별개입니다.

Android의 다음 조건은 안정적으로 실행되는 실기기 또는 KVM 가속 에뮬레이터, 정상 네트워크 경로, 사용자가 직접 수행하는 계정 로그인입니다. 같은 합성 화면에서 길게 누르기 → 대상 지정 → 전달을 먼저 확인하고, 이어서 로그인 후 Suno·Canva 입력칸을 시험해야 합니다. 기존 브라우저 대비 작업 시간 감소나 모든 플랫폼의 서비스 호환성이 입증된 것은 아닙니다.

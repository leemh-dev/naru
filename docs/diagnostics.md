# 진단 로그 수집 명세

사용자가 직접 설치해 시험하고, 오류 재현 정보를 나중에 공유하는 용도입니다. 기본 수집은 켜져 있고 앱 메뉴에서 끄거나 기록을 삭제할 수 있습니다. 서버 전송, 분석 SDK, 원격 제어, 계정 정보 추출은 없습니다.

## 형식과 저장

Electron userData 아래 `diagnostics/events-0.ndjson`부터 `events-3.ndjson`까지 순환 저장합니다. `events-0`이 약 512 KiB를 넘으면 이전 파일로 넘기고 가장 오래된 파일을 지웁니다. 마지막 한 줄 크기만큼 상한을 넘을 수 있습니다. 세션은 무작위 UUID로 구별하고 탭은 실행 내 숫자로 구별합니다. 파일 생성 권한은 지원하는 OS에서 0600으로 요청합니다.

내보내기는 JSON 하나입니다. 미리 보기에서 확인한 스냅샷을 사용자 지정 경로에 저장합니다. 앱 내부 URL 저장 파일, 브라우저 프로필, 쿠키 DB, 보관한 원문, 원시 런타임 로그를 함께 압축하지 않습니다. 디스크 저장에 실패하면 보고서의 `storageError`를 표시합니다.

## 수집 허용 목록

- 환경: 앱 버전, Electron·Chromium 버전, OS 종류·버전, CPU 아키텍처.
- 시각: 이벤트 발생 UTC 시각, 무작위 실행 세션 ID.
- 이벤트: 시작·종료·프로세스 오류, 탭 열기·닫기, 페이지 로딩·실패·렌더러 종료, 배치 변경, 입력칸 지정, 전달 결과, 자료 보관 건수, 보고서 저장, 진단 설정 변경, 로컬 복원 탭 수.
- enum: 서비스 종류(`src/services.json`의 정적 서비스 ID와 합성 시험 ID만 허용; 검색어·카탈로그 출처는 수집하지 않음), 제한된 상태·원인 코드, 배치 모드, 필드 종류(프롬프트/가사/스타일).
- 정수: 탭 번호, 소요 시간(ms), 글자 수, 줄바꿈 수, 건수, Chromium 오류 코드, 프로세스 종료 코드.

허용되지 않은 키·이벤트·enum 값은 저장하지 않습니다. 읽어 내보낼 때도 다시 허용 목록을 적용합니다. 원본 에러 객체·메시지·스택이나 웹사이트 console 출력을 그대로 넣지 않습니다. URL에서 개인정보를 정규식으로 지운 뒤 넣는 방식이 아니라 **URL 필드 자체를 수집하지 않습니다**.

## 해석 한계

- `page.load`는 로딩 종료 이벤트입니다. 로그인 성공, 화면의 기능 사용 가능, HTTP 오류 페이지의 의미를 증명하지 않습니다.
- `transfer.result: exact`는 삽입 직후 약 350ms의 원문 비교 결과입니다. 서버 제출·생성 성공이나 이후 화면 갱신 후 유지까지 의미하지 않습니다.
- `occupied`는 기존 입력을 발견해 전달을 멈춘 보호 결과입니다.
- `login`은 알려진 로그인 URL 경로 감지이며 모든 서비스의 로그인 화면을 판별하는 기능은 아닙니다.
- 강제 종료·전원 차단·초기 프로필 접근 실패처럼 로그를 기록할 수 없는 상황에서는 마지막 이벤트가 없을 수 있습니다.
- 글자 수·시각·사용한 서비스 종류도 사용 패턴을 드러낼 수 있으므로 내보내기 전 미리 보기를 확인합니다.

작업 복원을 위해 저장한 비공개 URL과 선택한 글은 로컬 작업 데이터이며 진단 로그와 다릅니다. 앱 데이터 폴더 전체를 공유하지 않습니다.
